Getting started

A local home for your simulations.

Set up the tools you need, then open MTS from a launcher in this folder. Your browser is the interface; your computer does the work.

1. Choose what you need

No login service

Python and its packages are managed for this workspace. Existing component checkouts are preserved. Missing submodules are downloaded at the versions recorded by MTS.

2. Run one command in Terminal

Open a terminal and paste the command below. You do not need to activate Python or navigate to this folder first.

The command prepares a Python runtime if necessary, then opens the setup progress in your browser. Keep the Terminal window open until installation is complete.

First installation needs an internet connection and Git. Use a Git clone of MTS; ZIP installation will be supported separately.

3. Open MTS whenever you need it

After installation, open MTS.app or MTS.desktop directly in this folder. It starts MTS and opens your browser. Nothing is registered to run when you sign in.

MTS.html links to the current browser session and provides startup help. Use the desktop launcher to start a new session, and Quit MTS inside the application to stop it.

You can close the browser tab and return to the same address while MTS is running. MTS stores an access token in your browser’s local storage solely to reconnect to that session; it is cleared when you choose Quit MTS. If browser storage is blocked or cleared, or MTS has stopped, reopen the desktop launcher.

Your operating system may ask you to approve a newly created launcher.

Working in Visual Studio Code (optional)

Open the top-level MTS folder after setup. Install Microsoft's C/C++ and CMake Tools extensions if you want to edit the simulator. Choose .venv/bin/python with Python: Select Interpreter for Python work.

  1. If CMake asks for a project, choose MTS2D/CMakeLists.txt, not a CMake file inside libs/. You can set cmake.sourceDirectory to ${workspaceFolder}/MTS2D in workspace settings.
  2. Choose the release configure preset. Presets require CMake 3.21 or newer. If a compiler selection appears on macOS, choose Apple Clang using /usr/bin/clang and /usr/bin/clang++. On Linux choose a supported GCC or Clang toolchain. C++17 is the language standard; you do not need a compiler named Clang 17.
  3. Use Terminal → Run Build Task → Build managed simulator, or the default build shortcut. This updates MTS2D/build/release/MTS2D and records the build identity required by the manager. The installer and GUI use the same Release build. After building directly through CMake Tools, run the managed task before starting managed simulations.

For simulator development, the optional debug preset uses MTS2D/build/debug. It keeps scientific tests separate from the Release executable used for simulations. Run MTS2D/build/debug/test_MTS2D after building the Debug preset.

Build folders and personal VS Code settings, compiler configuration and launch settings are ignored by Git. Shared build tasks and CMake presets are versioned. When changing a compiler, use a fresh build directory rather than moving a CMake cache.

Troubleshooting

Read the operation log in the Setup page for installation or build errors. Startup logs are stored in .mts/server.log and .mts/launcher.log in this folder.

If setup was interrupted, rerun the same command. If MTS is still running, quit it first or use its Setup page to repair packages. If the folder has moved, rerun setup to regenerate environment links and launchers.

The launcher can also be started from Terminal with the same command plus --start.

MTS supports macOS and Linux. Compiler installation is optional and uses system tools only when you select assisted setup.
